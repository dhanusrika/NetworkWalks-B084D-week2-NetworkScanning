## Overview

This repository documents my practical learning and hands-on activities completed during **Week 02** of the Networkwalks Cybersecurity Program.

The week's exercises focused on understanding how cybersecurity professionals perform information gathering, footprinting, OSINT, DNS enumeration, web technology identification, and network discovery using industry-standard tools.

All activities were conducted for educational purposes and within the authorized scope of the assigned exercises and my own local network.

## Learning Objectives

- Understand the fundamentals of footprinting and reconnaissance.
- Collect publicly available domain and DNS information.
- Identify website technologies and HTTP response headers.
- Understand Google Hacking Database (GHDB) and Google search operators.
- Explore OSINT and relationship analysis using Maltego.
- Perform domain information gathering with theHarvester.
- Discover active devices on a local network using Zenmap.
- Document findings and observations in a professional penetration testing report.

## Key Activities

### 1. Footprinting & Reconnaissance
Performed domain footprinting and information gathering using multiple Kali Linux tools to understand publicly available domain information, DNS infrastructure, web technologies, HTTP headers, and WAF detection.

### 2. Google Hacking Database (GHDB)
Practiced Google search operators and GHDB queries to understand how publicly indexed information can be discovered through search engines. The exercises emphasized responsible research and avoiding unauthorized access to exposed devices or sensitive information.

### 3. OSINT with Maltego
Explored Maltego's graphical investigation environment, entities, relationships, and transforms to understand how publicly available information can be connected and analyzed.

### 4. Domain Information Gathering with theHarvester
Practiced domain-based information gathering using theHarvester and explored how different public data sources can support the reconnaissance process.

### 5. Network Scanning with Zenmap
Used Zenmap to explore local network discovery, identify active hosts, examine IP and MAC address information, and understand network topology visualization.

# 6. Recommendations

Based on the observations from these activities, I recommend the following security improvements:

1.  **Review publicly exposed technology information**  
    Organizations should regularly review what information about their web technologies, CMS and plugins is publicly visible.

2.  **Keep software updated**  
    CMS platforms, plugins and other web technologies should be regularly updated and reviewed against current security advisories.

3.  **Review HTTP headers**  
    HTTP response headers should be reviewed to determine whether unnecessary technical information is being exposed.

4.  **Review DNS records regularly**  
    DNS records should be checked periodically to ensure that only required information and services are publicly exposed.

5.  **Properly configure and monitor the WAF**  
    Keep the WAF (ModSecurity) enabled and tuned, since it already blocks naive attacks.

6.  **Perform regular internal network discovery**  
    Organizations should periodically scan their own networks to identify active devices.

7.  **Investigate unknown devices**  
    Any unexpected device discovered during network scanning should be investigated and verified.

8.  **Maintain network documentation**  
    Network topology and device information should be documented and updated regularly.

9.  **Perform security testing with authorization**  
    Reconnaissance and scanning should only be performed against systems and networks where appropriate authorization has been provided.
